# 블라인드 화상 파티 기능 계획 (초안)

작성일: 2026-07-22  
브랜치: `megahuni`  
상태: `/autoplan` CEO 전제 검토 중

## 사용자 요청 원문 범위

- 현재 파티 기능과 별개인 새 파티 매칭 기능을 만든다.
- AI가 참여자의 성향을 바탕으로 남성 3명과 여성 3명을 한 세션으로 매칭한다.
- 여섯 명은 1:1 화상 대화 라운드를 진행한다.
- 첫 단계에는 변조된 목소리와 임의 캐릭터만 노출하고 별명과 성별만 확인할 수 있다.
- 남녀가 3쌍으로 나뉘며 상대를 바꿔 3분씩 총 3회 대화한다.
- 다음 단계에는 원래 목소리로 같은 방식의 3회 대화를 진행한다.
- 마지막 단계에는 얼굴을 공개하고 3분씩 대화한다.
- 모든 대화가 끝나면 프로포즈를 보내 계속 연락할지 결정한다.
- 최종 결정 시간은 10초다.
- 빠른 데모가 아니라 디자인, 사용성, 안전, 장애 복구, 테스트를 포함한 프로덕션 수준으로 완성한다.

## 검토가 필요한 전제

- 성별과 관계 선호를 어떻게 명시적으로 동의받고 3:3 큐 자격을 정할지
- 얼굴 공개 전 카메라와 원음이 기술적으로 상대에게 전달되지 않도록 하는 보안 경계
- 마지막 단계가 한 번의 3분 대화인지, 세 상대와 각 3분씩 총 3회인지
- 10초 결정이 거절 압박을 만들지 않으면서 요청 의도를 지키는 상호 선택 방식
- 27분 이상의 세션에서 이탈, 재접속, 노쇼, 신고, 네트워크 저하를 처리하는 정책
- 실시간 음성 변조와 화상 통화를 제공할 미디어 기술 및 운영 방식

## 제안하는 제품 정의

작업명은 **블라인드 로테이션**으로 둔다. 기존 게임 파티는 함께 플레이하며 친해지는
비동기성이 강한 경험이고, 새 모드는 정해진 시간 동안 여섯 명이 집중해서 대화하는
실시간 이벤트다. 따라서 기존 파티의 화면과 데이터 모델에 모드를 억지로 끼우지 않고,
홈에서 `파티 선택`을 거쳐 두 경험으로 분기한다.

### 권장 참여 자격

- 이 모드에 별도로 동의한 만 19세 이상 활성 사용자만 큐에 들어간다.
- `남성/여성` 성별 값만으로 이성애 선호를 추론하지 않는다. `만나고 싶은 성별`을
  프로필에 명시적으로 추가하고, 이번 3:3 큐는 남성-여성 상대를 허용한 사용자만 받는다.
- 논바이너리와 성별 비공개 사용자를 앱에서 배제하지 않지만, 고정 3:3 구조인 이번 모드의
  첫 출시에는 포함하지 않는다. 더 포괄적인 조 편성 규칙은 별도 제품 범위로 남긴다.
- 차단 관계, 계정 상태, 위험 점수 정책, 최근 중복 만남, 기기 권한/네트워크 사전검사를
  매칭 전에 확인한다.

### 권장 세션 구성

세 상대에게 공정한 기회를 주기 위해 마지막 얼굴 공개도 3회로 해석한다. 총 대화 시간은
`3단계 × 3회전 × 3분 = 27분`이며, 시작 준비와 전환 및 최종 선택을 포함하면 약 31분이다.

```text
준비실(6명 모두 준비)
  → 1단계: 캐릭터 + 변조 음성       3분 × 3회전
  → 2단계: 캐릭터 + 원래 음성       3분 × 3회전
  → 3단계: 얼굴 + 원래 음성         3분 × 3회전
  → 비공개 최종 선택                 10초 확인
  → 상호 선택만 매치/채팅 생성
```

회전 편성은 한쪽 그룹을 고정하고 다른 쪽 그룹을 순환시켜 모든 교차 조합을 정확히 한 번
만든다. 서버가 회전 번호와 종료 시각을 결정하고 클라이언트 시계는 표시용으로만 쓴다.

```text
회전 1: M1-F1, M2-F2, M3-F3
회전 2: M1-F2, M2-F3, M3-F1
회전 3: M1-F3, M2-F1, M3-F2
```

### 10초 선택의 안전한 해석

10초 안에 처음부터 사람을 평가하게 하지 않는다. 각 대화가 끝날 때 상대를 `다시
대화하고 싶어요` 목록에 비공개로 저장할 수 있고, 마지막 10초는 이미 만든 선택을 확인하고
제출하는 시간으로 쓴다. 시간 초과는 자동 프로포즈가 아니라 `선택 없음`이다. 상대가 나를
선택했는지, 거절했는지는 공개하지 않고 상호 선택일 때만 매치와 1:1 채팅을 만든다.

## 미디어 기술 방향

React Native/Expo 개발 빌드와 네이티브 iOS/Android를 지원하고, 송출 전에 로컬 음성 효과를
적용할 수 있는 `react-native-agora`를 우선 후보로 둔다. 공식 React Native SDK 인터페이스는
`setVoiceConversionPreset`, `setLocalVoicePitch`, `setLocalVoiceFormant`를 제공한다. Expo Go는
네이티브 WebRTC SDK를 실행할 수 없으므로 EAS development build/실기기 QA를 배포 파이프라인에
포함한다. LiveKit은 Expo 통합과 트랙 권한 모델이 훌륭한 대안이지만, React Native에서 제품이
요구하는 음색 변조를 별도 네이티브 프로세서 없이 바로 제공하지 않아 현재 요구에는 Agora가
더 직접적이다.

프라이버시 경계는 UI가 아니라 송출 권한이다.

- 1단계: 마이크만 발행하며 로컬 변조 효과가 적용된 트랙만 전송한다. 카메라 캡처/발행 금지.
- 2단계: 음성 효과를 제거한 마이크만 발행한다. 카메라 캡처/발행 금지.
- 3단계: 별도 얼굴 공개 동의와 준비 상태를 확인한 뒤에만 카메라를 캡처하고 발행한다.
- 매 회전마다 해당 1:1 채널에만 들어갈 수 있는 짧은 수명의 서버 발급 토큰을 사용한다.
- 녹화와 클라우드 레코딩은 기본 비활성화하며 원본 음성/영상은 애플리케이션 서버에 저장하지 않는다.

참고한 공식 자료: [LiveKit Expo quickstart](https://docs.livekit.io/home/quickstarts/expo),
[LiveKit React Native SDK](https://github.com/livekit/client-sdk-react-native),
[Agora React Native SDK](https://github.com/AgoraIO-Extensions/react-native-agora).

## 초기 상태 기계

```text
QUEUED
  → MATCHED → PREFLIGHT → READY_LOCKED
  → CONVERSATION(stage=1..3, rotation=1..3)
  ↔ RECONNECTING(grace 제한)
  → CHOICE_OPEN(10s) → RESOLVING → COMPLETED

모든 진행 상태 → ABORTED(안전 이탈/인원 부족/운영 중단)
```

서버는 `sequence`, `state`, `stage`, `rotation`, `phaseEndsAt`을 영속화한다. 모든 명령은 세션
멤버십과 현재 sequence를 검증하고 멱등성을 가져야 한다. 클라이언트 재접속 시 이벤트를 추측해
재생하지 않고 현재 스냅샷을 받아 정확한 채널과 남은 시간으로 복구한다.

평가했다. 특히 한 명의 노쇼가 다섯 명의 시간을 망치고, 음성 변조·3분·단계 공개·10초가
행동상 유효하다는 근거가 없으며, AI 매칭이 기준군보다 낫다는 평가 체계와 얼굴 공개 안전
정책이 부족하다고 지적했다. 권장 보완은 예약 코호트, 대기자, 단계별 지표, AI 기준군,
상대별 공개 동의, 실기기 미디어 스파이크다.

#### CODEX SAYS (CEO — strategy challenge)

Codex CLI는 인증과 실행에는 성공했지만 두 번 모두 계획을 읽은 뒤 최종 검토문을 반환하지
않았다. 첫 실행은 명시한 파일 경계를 어기고 외부 스킬 정의를 읽었으므로 결과를 폐기했다.
따라서 이 단계는 `[subagent-only]`로 표시하며 Codex 부재를 합의로 간주하지 않는다.
