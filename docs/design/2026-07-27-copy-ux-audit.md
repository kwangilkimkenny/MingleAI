### D. 낮은 우선순위 / 참고

- `verify-identity.tsx:80` "(개발용 입력)" — 실키 연동 전 스텁 안내. `__DEV__` 조건부 표시로 바꾸면 베타 화면에서 사라짐.
- `NaverMap.tsx:37` "지도는 앱 빌드에서 표시돼요" — '앱 빌드' = 개발 용어. 실기기 EAS 빌드에선 안 보이는 폴백이므로 낮음. 대안: "지도를 준비하고 있어요".
- 한국어 줄바꿈이 단어 중간에서 끊기는 곳(예: "(개발용 입/력)") — RN 기본 글자 단위 줄바꿈. 필요 시 `Text`에 `textBreakStrategy="balanced"`(Android) 적용 검토. 시스템 전반 사안이라 별도 패스로.
- 이미 잘된 것: 홈 헤드라인("얼굴보다\n대화가 먼저" — 의도된 줄바꿈), 룰 5단계, 추천 질문 30개, 세션 안내, 약관·개인정보(2026-07-27 현행화, 문서 톤 합쇼체 일관) — 수정 불요.

## PART 2 — 모바일 UI/UX 설계 원칙 분석 (전문가 관점)

### 근거 원칙

1. **엄지 도달권(Thumb Zone).** 모바일 사용자의 절반 가까이는 한 손 엄지로만 조작한다(Steven Hoober의 관찰 연구: 한 손 조작 ~49%). 엄지가 편하게 닿는 곳은 **화면 하단 ~중앙**이고, 상단 절반·모서리는 '스트레치/하드' 구역이다. → **탭 대상(버튼·체크박스·칩·입력)은 화면 세로 중간선 아래에 두는 것이 원칙**. 사용자가 말한 "클릭 버튼은 화면 중간을 넘어가지 않는다"가 정확히 이 원칙이다.
2. **Fitts의 법칙.** 타깃 획득 시간은 거리와 크기의 함수. 직전 터치 지점(대개 하단)에서 가까울수록, 클수록 빠르다. 연속 동작(체크 → 계속)은 같은 구역 안에서 끝나야 한다.
3. **터치 타깃 최소 44pt(iOS)/48dp(Android) + 타깃 간 8dp.** 현재 앱은 `control.minTouch` 준수 — 유지.
4. **여백은 위계 도구다.** 콘텐츠가 상단에 몰리고 하단 40%가 상시 비는 화면은 '숨 쉬는 여백'이 아니라 레이아웃 미완이다. 여백은 그룹 경계에 쓰고, 인터랙션 무게는 아래로 내린다.
5. **파괴적 동작은 예외.** 계정 삭제·차단 같은 동작은 의도적 마찰(도달 난이도·확인 문구)이 정당하다 — 편의성 원칙을 역적용.

### 화면별 진단 → 권고

| 화면 | 진단 | 권고 |
|---|---|---|
| **동의(consent)** | 체크박스 3→2개가 **화면 상단**에 몰림, 카드 아래~CTA 사이 거대 공백. 체크(상단) → 계속(하단)으로 엄지 왕복 | **체크 카드를 하단 CTA 바로 위로 내려 하단 정렬**. 상단은 타이틀만. 체크·계속이 같은 썸존에서 끝남 — 이 화면의 유일한 과업이 '체크 후 계속'이므로 효과 가장 큼 |
| **본인인증 폼** | 필드 4개가 상단부터 시작, 아래 1/3 공백 | 폼 스택을 **하단 정렬**(타이틀 아래 여백을 위로). 첫 필드 포커스 시 키보드 위에 폼이 놓여 스크롤도 줄어듦. 필드 간 gap 한 단계 축소(x5→x4) |
| **온보딩 프로필** | 아바타+필드 3개, 스크롤 발생. 필드 간격 넓음 | 사진 영역 축소(104→84), gap x5→x4 — 한 화면에 수렴. CTA 하단 고정은 이미 올바름 |
| **설정** | 리스트가 상단 절반, 하단 절반 공백 | 항목이 6개뿐이므로 **섹션을 하단으로 내리는 것보다, 프로필 카드(내 정보 요약)를 상단에 크게** 두어 상단을 '보는 영역', 하단을 '누르는 영역'으로 재배치. 로그아웃·계정 삭제가 최하단에 오는 현 순서는 유지(파괴적 동작) |
| **차단 관리·채팅·네이버 빈 상태** | 중앙 배치 | 표준 패턴 — 유지. 단 CTA 있는 빈 상태(채팅 "블라인드 데이트 시작")는 CTA를 중앙 대신 **하단 고정**하면 썸존 일치 |
| **룰(rules)** | 정보 5줄 상단, 중간 공백, CTA 하단 | 인터랙션이 '다음' 하나뿐이라 심각도 낮음. 룰 리스트 세로 중앙 정렬로 균형만 잡으면 충분 |
| **위치 스텝** | 풀블리드 지도 + 하단 칩 일렬 + CTA | **모범 사례** — 모든 조작이 하단 1/4. 변경 불요 |
| **홈** | MATCH가 하단 1/3 — 모범. 하트·벨은 우상단(hard zone) | MATCH 유지. 하트·벨은 저빈도+배지 유인이라 허용 범위. 장기적으로 최근 활동 행을 하단에 두는 원안 재검토 여지 |
| **세션(라운드·인트로·결정)** | 이머시브, 결정 카드·선택 버튼 하단권 | 유지. 추천 질문(하단 1/3)도 시선 동선과 일치 |
| **계정 삭제** | 입력 상단, 버튼 최하단, 사이 공백 | **의도적 마찰로 정당** — 예외 원칙. 유지 |
| **채팅방** | composer 하단, 오프너 칩 중앙 | composer 모범. 오프너 칩을 composer 바로 위로 내리면 탭→전송 동선 단축 |

### 공통 설계 규칙 제안 (AppScreen 아키타입에 반영)

1. **"결정 화면" 하단 정렬 규칙**: 화면의 과업이 '읽고 → 1~2개 조작'이면 조작 요소(체크·칩·필드)를 하단 CTA 위에 붙인다. 상단은 타이틀·설명만.
2. **폼 밀도 토큰**: 폼 화면 gap 기본 x4(16), 라벨-필드 8, 섹션 24. 현재 x5+큰 input이 스크롤을 만든다.
3. **모든 primary CTA는 화면 하단 고정**(AppScreen footer) — 이미 관철됨. 신규 화면도 예외 없이.
4. **탭 대상 세로 위치 기준선**: 반복 조작 요소는 화면 세로 55% 아래. 위반이 필요한 경우(파괴적 동작·저빈도 헤더 액션)만 예외.
5. **여백 감사 기준**: 정적 화면에서 뷰포트 하단 1/3이 완전히 비면 레이아웃 재검토(빈 상태 화면 제외).

### 적용 우선순위 (승인 시 작업 순서)

1. consent 하단 정렬(효과 최대·1파일) → 2. 폼 밀도(identity·onboarding·profile-edit) → 3. 채팅 오프너 칩 위치 → 4. 설정 상단 프로필 카드 → 5. 빈 상태 CTA 하단 고정.
